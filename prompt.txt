给下面的产品或开源项目起英文名字，可用作 npm 包名、GitHub 仓库名或产品名。英文名用拉丁字母，不等于只能选英语字典词：可用紧凑复合词、自然造词、利落短实词、跨语种短词、拼音或简拼主体，以及适度前缀装饰。

核心原则（先读再动笔）：
1. 名字与定位句分工：好名字（如 Vite、Supabase、Dify、Vercel、Pake、Firecrawl、Filepond、Trufflehog、Caddy）不靠名字背完功能说明书。名字负责「像独立品牌、短促好打、带一个具体动作或场景切口」，具体品类与规格由随后的一句话介绍补足。不要为了“看名字就懂全部参数”而硬塞功能词拼成说明书。
2. 命令行与首屏测试：把每个候选放进 `npx <packageName>` 和官网首屏「X — 一句话定位」读一遍，必须像一个独立产品名。严禁把配置开关/HTTP 头（no-store、no-cache、zero-copy、http-first）、格式或数量标签（json-envelope、direct-json、directnine）、或「泛动词/形容词 + 泛对象」（direct-link、parse-link、clean-link、open-link、hey-parse、try-direct）当成名字。

输入（缺项先问，不要自己编）：
产品描述（一段话，写清产品是什么、关键动作和不做什么）：{{产品描述}}
名字用在哪：npm 包名 / GitHub 仓库名 / 产品名（可多选）
语言：英文
同类产品（用来避让撞名）：{{已知同类产品}}
不想要的名字类型：{{最讨厌的名字类型}}
已否决的名字：{{已否决候选}}
名字数量：{{数量}}

起名前排查（必做，跟核验同级，不查不起名）
- 同名项目：GitHub 搜 <候选名>+in:name 看仓库数与 star，npm 查 registry.npmjs.org 返回码，web_search 搜一圈。同名仓库数只做参考，star 高且仍在维护的才算真撞名，撞名的直接避让不硬用。
- 同类产品：web_search 搜产品描述里的关键词加工具、项目、开源，列出已存在的同类。名字跟同类产品撞车的直接避让，哪怕名字本身没被注册。输入里没填同类产品的，主动查出来补上，不靠用户给。
- 排查结果写进 analysis.factsKnown（已占用与已存在的同类清单），供取材与评审避让用。如当前环境无联网工具，在 factsGaps 注明未联网查竞品。

运行时流程
1. 产品描述缺失或含糊时，一次列出问题，等回答后再起名，不编事实。其他项可填“无”或“待确认”；名字数量留空默认 8 个，用户指定数量时按指定值。
2. 先排四条命名路线与配比再发散（默认 8 个名额，其他数量按比例折算；某类配不出合格名就整条放弃并写进 factsGaps，不为凑类型硬造）：
   - 路线 A · 紧凑具象复合词（2-3 个）：两个短小、有画面感的英语真词（具体动作 + 具体载体/场景）合成一个紧凑单件词，如 Firecrawl、Filepond、Trufflehog、Tailwind。取的是动作画面或物理隐喻，不是把输入原词直接拼成 direct-link、parse-link。
   - 路线 B · 自然造词或短写变形（2-3 个）：4-9 个字母、2-3 音节，由产品核心动作或领域词根咬合（portmanteau）、裁剪或轻度变形而成，每个音节有元音、无连续 3 辅音、一读就能拼对，如 Supabase、Dify、Vercel、Crawlee、Typst。造词不用写词源故事，但读起来必须自然顺口，不能像乱码。
   - 路线 C · 利落短实词或跨语种动作短词（1-2 个）：1-2 音节（4-7 字母）的具体英文动作/物件词（与产品核心机制有直接物理对应，如 Caddy、Sharp、Unreel；不要跟产品毫无关联的冷僻器物），或跨语种动作短词（外语里恰好等于产品核心动作的 2 音节开音节词，如克里奥尔语打包 Pake、日语书写 Kaku、日语火焰 Hono，要求罗马字一读就对、不靠典故）。
   - 路线 D · 前缀装饰 / 自然短语 / 拼音专名（1-2 个，上限 2 个）：招呼前缀加独特主体（前缀后必须是造词或具象复合词，严禁接裸动词或通用词）；连写自然口语短语（如 NameYouLike）；或含中文专名/编号时的拉丁拼音/简拼-用途词（如证书编号前缀 CCRDS /「传承人大赛」→ ccrds-cert、`guizang-ppt-skill`）。
3. 先广度发散再收敛：在内部先沿四条路线发散至少 16-20 个候选，再逐个过审。取材从产品自己的核心动作、输入输出形态变化、运行机制或体验特征做「具象转化」（例如把“剥除水印返回直链”转化为剥壳 peel、解卷 unreel、揭戳 unstamp、裸片 bareclip、包裹解析咬合 parsel，而不是直接贴规格词 no-store、direct-link、json-envelope）。不同产品应使用该产品自己的动作与场景意象，不套用固定词表。
4. 用下面同一套判据逐名评审：先过「命令行与首屏测试」剔除所有功能标签与配置开关，再按产品关联、词面与可读性、避免套路、形态、可用表达检查。保留要有证据，淘汰要点名规则和补充方向；不得只改解释救回标签名或不相关名字。
5. 过审不足名额时，换来源或角度补新名，补进来的重新评审。同批检查发现家族扎堆时，即使名额已满也要换掉扎堆的候选再补，不要带着扎堆交付。所有已保留、已否决和本轮淘汰的名字都不再生成，只差字母、后缀、同义词或同一主体变体也算重复。不能降标准、加通用后缀凑数或把补齐任务交回用户。
6. 交付前核对 names 实际条数与 analysis.reviewed.kept，起名模式下都必须等于名额；再按同批检查数一遍家族计数写进 analysis.familyCheck：列出每个候选名里出现的词根及其次数，保留名和淘汰名都算在次数里，任何一个词根或同模板超过 2 个、或出现前缀变体对就先换掉多余的再输出，不带着违规交付。只有输入事实不足或可用方向确实耗尽时才允许短交，在 factsGaps 写明缺什么、为什么补不出，并提出需要补充的问题。记录补齐轮数、补上几个和逐名淘汰理由。**交付前必须跑完核验**：能联网或执行命令时，每个保留名的域名走 RDAP 查实、npm 查 registry 返回码、GitHub 查用户名与同名仓库数、商标查 USPTO/CNIPA，全部写进 riskNotes 再交付，域名可注册但 npm、GitHub、商标任一被占用的直接淘汰换新；若当前环境无联网或执行工具，在 riskNotes 和 factsGaps 如实标明“未确认（无联网工具）”，绝不伪造已查结论。
7. 若用户注明“本次只评审”并提供已有候选，沿用下面判据，逐名输出 verdicts，不起新名、不要求凑满 8 个。计划或历史名单没提供就跳过对应核对，不因此判待定；产品事实缺失仍先问。

名字形态
- npm 包名、GitHub 仓库名（packageName）：全小写字母、数字、连字符，名字本体不超过 15 个字符（拼音-用途词可适当放宽）；不用空格、下划线、大写、版本号、日期或 js、py 后缀，要能读出来，不是 fsdk2。
  - 单件复合词、自然造词、连写短语（如 Firecrawl、Linkpeel、Bareclip、Parsel、Unreel、NameYouLike），packageName 保持全小写单件连写（firecrawl、linkpeel、bareclip、parsel、unreel、nameyoulike），不硬拆连字符。
  - 带前缀装饰、分立双词或拼音-用途词（如 Try Parsel、Hey Bareclip、ccrds-cert、guizang-ppt-skill），packageName 按词界用连字符连接（try-parsel、hey-bareclip、ccrds-cert）。
- 产品名：英文主名，只出英文。本项目不做汉字名，也不把中文词当主名；需要中文对应的拉丁变体时，只给拼音、简拼、拼音-用途词、连字符这些拉丁字母写法（如赛事、机构、公文或单据项目，优先取其真实编号前缀或专名核心词简拼加交付物词，如证书编号前缀 CCRDS /「传承人大赛」→ ccrds-cert，既不逐字直译成冗长口水名，也不抹掉业务专名退化成纯通用工具词），先说明对应的中文主体与产品事实，不能靠补一个用途词救回不相关主体，同一主体的变体不占多个名额。
- 名字来源不限于字典词：紧凑复合词、自然造词（读起来像真词，比如 cobalt、dify、supabase、vercel）、跨语种短词（Pake、Kaku、Hono）、利落实词、招呼前缀加独特主体，都是合格来源。
- 不要「文化意象 + 实字」的拼接怪：把器物、神话、山水意象当主体再接一个功能词（墨舟、灵枢、云篆、北斗尺这类）只是拼字，不像真实产品名；文化或自然意象必须整体单件（如 Kylin、Hermes）且生态适配。
- 前缀装饰：前缀用来给名字搭话或点出场景，按下面的路线挑，一批里最多 2 个（1-2 个即可，宁缺毋滥）：
  - 亲切互动：hey-、hi-、hello-、meet-、join-、with-（如 hey-parsel、meet-caddy 这类用法）
  - 产品动作：get-、try-、go-、run-、make-、build-（如 try-bareclip、get-unreel 这类用法）
  - 归属感：my-、our-、we-、the-、one-（如 one-parsel 这类用法）
  - 招呼式：try-、ohmy-、yo- 等（ohmy 占用很高，npm 搜 oh-my- 约 16 万条、GitHub 一万多个仓库，主体必须足够独特才用）
  前缀只负责搭话，含义主要由主体承担。主体必须是独特的造词或具象复合词；前缀接裸动词、通用技术词或功能词（hey-parse、try-direct、one-envelope、try-app、try-tool、get-ops、meet-data）直接判不成立。
- 每个名字给 2-3 个域名候选：优先 .dev、.io、.app，其次 .com、.net、.sh、.xyz、.co、.ai。域名必须照 packageName 原样拼写，只换后缀（packageName 是 try-parsel 就写 try-parsel.dev，packageName 是 linkpeel 就写 linkpeel.dev）。候选在下面的「核验」段逐个查实，查到的写状态与来源，查不清的写「未确认」。

核验（起名交付前尽量跑完；无联网或执行环境时诚实标「未确认」）
- 状态六选一：可注册、已注册、溢价、保留、挂牌出售、未确认。查不清、无网络或查询出错就写「未确认」，不写「可能可用」，不把 429、超时、空响应当可注册。
- 每个后缀只有一个权威 RDAP，用错源会拿到假的 404：.com/.net 用 rdap.verisign.com/{com|net}/v1/，.io/.ai/.sh 用 rdap.identitydigital.services/rdap/，.dev/.app 用 pubapi.registry.google/rdap/，.xyz 用 rdap.centralnic.com/xyz/。聚合站（rdap.org 之类）实测时好时坏，时而 403、跳转或限流，不拿它的结果下结论，结论只认注册局基址。
- 请求写成 GET <基址>domain/<域名>。404 = 没有注册记录；200 = 有记录：响应里带 reserved 字样写「保留」，带 premium 字样写「溢价」，否则写「已注册」，并从 events 的 registration、expiration 和 entities 里的 registrar 读创建时间、到期时间、注册商；429 = 限流。
- 限流按后缀分开：.dev/.app 限流最严，串行、间隔 400ms；其他后缀并发 2 即可。429 按 0.8s、2s、4s 退避重试，三次还 429 就写「未确认」。
- WHOIS 只兜底：com/net/io/ai/me/sh/so 可用（whois <域名>，出现 Registrar、Creation Date 为已注册；「No match for」是 .com/.net 未注册，「Domain not found」是 .io/.me/.sh 未注册）。.dev/.app 的 WHOIS 实测对已注册与不存在的域名都回空串，不走这条路。
- DNS 不能单独下结论：查到 NS 记录可直接判已注册；NXDOMAIN 只说明没有委派，已注册但没配 NS 的域名也长这样，得回 RDAP 确认。本机 DNS 可能被代理劫持编造假地址，不用解析结果判断可用性。
- 同一后缀不并发轰炸；同一域名两次结论一致才写状态。仓库脚本 scripts/domain-check-fast.py 实现了这套查询链（DoH 预筛、权威 RDAP、WHOIS 兜底），加 --full 可一键联查域名、npm、GitHub 以及多源品牌/商标库（本地 8200+ 中外品牌与上市公司字号库、Wikidata 商标/软件实体、App Store 美/中区在营软件）：python3 scripts/domain-check-fast.py --variants linkpeel,bareclip --full --json out.json。
- 可注册不等于能用：npm 包名占用、GitHub 同名仓库、品牌与商标冲突必须逐项查清并报实测结果。npm 查 registry.npmjs.org/<包名> 返回码（404 未占用、200 已占用）；GitHub 查 github.com/<名> 返回码（404 用户名未占用）加 api.github.com/search/repositories?q=<名>+in:name 看同名仓库数；商标与品牌先用脚本 --full（或 --brand-only 离线）过一遍本地 8200+ 中外品牌库、Wikidata 国际商标/软件实体与 App Store 美/中区在营软件，正式商标确权查 USPTO tmsearch 与 CNIPA 商标库，查到记录报注册号与状态，未登录官方库时写明已跑过哪些公开库初筛并注明官方库待核验；无法联网时写「未确认（无联网工具）」。同名产品用 web_search 搜一圈。已证实 npm、GitHub 高星活跃项目或商标/品牌碰撞的直接淘汰换新，不靠改解释救回。
- 交付写明：查了哪些域名、各自状态与来源（rdap / whois / doh-ns / 未确认）、查询时间；没查的只叫候选域名。

共用评审判据（每个候选都检查，不再另写自检清单）
- 命令行与首屏测试：放进 `npx <packageName>` 和「X 是一个……」以及同类产品网站首屏标题的语境，必须像一个独立产品名而不是说明书标签。配置开关/HTTP 头（no-store、no-cache、zero-copy、http-first）、格式或数量标签（json-envelope、direct-json、directnine）、泛动词+泛对象（direct-link、parse-link、clean-link、open-link、hey-parse、try-direct）直接淘汰。
- 来源与联想：来源可以是紧凑动作画面复合词、自然造词、利落短实词、跨语种动作短词或招呼前缀加独特主体。自然造词只要读起来像一个词、节奏流畅、有方向感就算合格，不要求字典里查得到，也不要求拆词根作文。真实词要列三条不同联想（物件、场景、日常用法）；造词与前缀名列两条可感知的联想（读音与节奏带来的感觉、动作或场景指向）。不编词源故事、创始人故事或市场数据。
- 产品关联：productFact 引用输入中的原词，理由说清名字如何映射到产品的核心动作、输入输出变化、运行机制或体验切口；“提升效率”“更简单”“有科技感”“朗朗上口”不算证据。允许“名字承担识别与切口 + 介绍句补充具体品类”的分工，不要求名字写全所有技术参数，但词义方向必须与产品边界一致，不能把无状态只读解释成囤积/信息流（如不存储内容却叫 feed/store/hoard），不能把独立处理解释成汇聚（fold/funnel），不能把后台能力写成无关的抽象器物（龙头、夹板、火石、放大镜）而毫无动作或场景线索。
- 词面与可读性：短、好打、好记，念出声清晰，听一遍能拼出。单件核心名以 4-10 个字母、2-3 个音节为佳（超过 12 字母或 5 个音节先换短再交付），每个音节有元音、避免连续 3 个以上辅音。不要两个通用褒义词或抽象名词拼接（Bridgescape、Flybridge、Gainbridge），不要靠外语生僻典故才通的名字（Ikena）。词首爆破音（k/p/t/d）读着利落，前元音（i/e）偏快偏小、后元音（o/u）偏慢偏大，仅在同分取舍时参考。
- 套路拦截：不用通用词加 -ly/-ify/-io/-ai/-hq/-labs/-base/-flow/-wise/-verse/-nova/-gen/-mint/-ora/-eon/-ium 批量造名，不用 elevate、empower、seamless、innovate、future、vision、unleash、limitless 或“类别词 + AI”。不用灯塔、指南针、雷达、哨兵、信标、地图册、守望塔、守卫、盾牌等通用监控隐喻，不用漏斗、交叉口、交换机、校验和、数据包或 Courier、Waybill、Parcel、Relay、Package 等泛泛行业标签套泛化关联。
- 形态自查：逐个核对 packageName 是否符合连字符规则（单件复合/造词不强拆，前缀/双词/拼音用连字符）、domains 字段是否有 2-3 个候选、是否照 packageName 原样拼写、是否无遗漏后缀。
- 同批检查：四条路线分布均衡，不全挤在一个结构或意象族；数一遍每个词根在全部候选（含保留和淘汰）里出现的次数，任何一个词根或同模板超过 2 个就换掉多余的；同一主体的前缀/后缀变体（Parsel 与 Try Parsel、Linkpeel 与 Linkpeels）算重复，只留 1 个；不照抄示例、不换字仿写、不续写同系列。撞同类产品或高星活跃同名项目的直接淘汰换新，不靠改解释救回。

输出
缺项时只列问题，不出名字。起名完成后给两种输出：先用列表读给人看，再给 JSON 给程序读，两者内容必须一致；解释用中文，不要长篇分析、词源故事或综合评分。列表一行一个名字，写成「序号. 名字（包名）· 读音 · 域名（状态）· npm/GitHub/商标核验 · 一句话由来」，域名逐个标可注册、已注册、溢价、保留、出售或未确认，npm 标占用/未占用/未确认，GitHub 标用户名占用与否与同名仓库数（或未确认），商标标查到注册号/未见记录/未确认，不重复 JSON 里的联想和长理由。JSON 只放结构化字段，数字用整数，kept 按实际条数填写，rejected 列出本轮所有已淘汰的名字，不只写总数。
{"analysis":{"factsGaps":[],"factsKnown":[],"topUp":{"rounds":0,"added":0},"familyCheck":[{"word":"词","count":1}],"reviewed":{"kept":8,"rejected":[{"name":"淘汰名","reason":"规则与证据","suggestion":"新取材方向"}]}},"names":[{"name":"英文主名","packageName":"小写或连字符包名","source":"真实来源或造词思路，简短说明是什么","associations":["联想一","联想二","联想三"],"productFact":"引用输入原词","rationale":"一句话说明来源与产品事实的联系","pronunciation":"读法","domains":["候选域名一","候选域名二","候选域名三"],"riskNotes":"同音、拼写、撞名风险；填域名、npm、GitHub、商标的实测核验结果或未确认"}]}
只评审时同样先给列表（每行「名字 · 保留或淘汰 · 一句理由」），再输出 {"verdicts":[{"name":"候选名","decision":"keep|reject","reason":"引用规则和具体证据；保留的也给证据","suggestion":"淘汰时的新方向"}]}，每个输入候选恰好一条。
只交英文名：names 里每条都是英文名，不出现汉字；拼音、简拼、拼音-用途词只以拉丁字母写法出现，不替代英文主名。
